  3043→## 34.2 AI Component Evaluation Methodology
  3044→
  3045→The appeal letter is the central artifact; its quality is evaluated on a 5-dimension rubric adapted from the ADK evaluation framework [B-26]: (1) Factual accuracy — every statement of fact in the letter (payer policy clause, regulation citation, medical record reference) is verifiable against source documents; (2) Citation correctness — every cited clause exists and supports the claim being made; (3) Persuasive structure — the letter follows the canonical appeal-letter structure (intro → denial reason restatement → legal/policy basis → medical-necessity evidence → request for reconsideration → deadline reference); (4) Payer-format compliance — the letter meets the specific payer's submission requirements (length, format, required fields, submission channel); (5) Tone — professional, assertive, non-confrontational (the Gemma fine-tune's job). Each dimension scored 1-5 by Gemma-as-judge (calibrated against 10 human-scored reference letters); a human spot-checks 1 letter per demo rehearsal. Disagreement &gt;1 point between Gemma and human triggers prompt iteration on the judge prompt.
  3046→Citation accuracy and denial classification accuracy are evaluated deterministically. Citation accuracy: every cited clause ID in a drafted letter is looked up in pgvector; if found, the cited clause text is compared (semantic similarity &gt;0.85) to the claim it's cited for. Denial classification accuracy: 50 synthetic denial letters are human-labeled with the expected denial type; the Denial Triage Agent is run on all 50; accuracy = correct / 50. The 50-letter test set is held out (not used in prompt development).
  3047→
  3048→## 34.3 Outcome Learning Agent Improvement Measurement
  3049→
  3050→The Outcome Learning Agent's improvement is the hardest metric to measure in 14 days because real longitudinal outcome data doesn't exist yet. The measurement strategy has three components. Component 1 — Synthetic outcome corpus: 50 synthetic outcomes are pre-seeded, each labeled with payer × denial type × outcome (win/loss) × winning-clause-ID. The Outcome Learning Agent ingests these on Day 4; the before/after retrieval weights are logged. Component 2 — Visible weight delta: after ingesting a "win" outcome for a specific clause, the clause's retrieval weight must increase by ≥0.05 (clamped learning rate). This is the visible learning signal. Component 3 — Held-out evaluation: 10 held-out synthetic cases are run before and after Outcome Learning ingests the 50 outcomes; the held-out cases should retrieve the winning clauses more often after learning than before. Target: ≥20% improvement in top-3 retrieval accuracy on held-out cases. This is the canonical "self-evolving agent" claim made measurable — exactly the Aug 20 webinar theme [A-5].

  3189→# 38. Open-Source Strategy
  3190→
  3191→Open-source strategy is a strategic moat decision, not a generosity decision. The right open-source posture attracts developers (who contribute adapters, MCP servers, edge-case test cases), attracts users (who try the open-source version and convert to paid), and creates ecosystem lock-in ethically (the open-source primitives become the standard, but the proprietary data retains the value). DenialDefender's open-source strategy follows the "open primitives, closed data" model that MongoDB, Elastic, and Confluent used successfully (with their own governance lessons).
  3192→
  3193→## 38.1 What Should Be Open-Source
  3194→
  3195→Three categories of artifacts are open-sourced under Apache 2.0. First, the agent orchestration framework adapters — the ADK 2.0 GraphWorkflow definition, the SequentialAgent / ParallelAgent / LoopAgent patterns DenialDefender uses, and the wrapper code that integrates ADK with GEAP components. These are useful primitives for any developer building multi-agent fleets on Google Cloud, not just healthcare-specific. Open-sourcing them establishes DenialDefender as a reference architecture for the broader Google agentic ecosystem. Second, the MCP tool servers — the payer-policy lookup MCP server, the medical-record structuring MCP server, the deadline-tracking MCP server. These are useful MCP servers for any healthcare-adjacent agent project. Open-sourcing them contributes to the MCP ecosystem and signals Google's open-standards posture (MCP is Anthropic-led, Google-supported per Phase B). Third, the synthetic denial letter dataset — 50-100 fully synthetic de-identified denial letters covering the top 5 payers × 10 denial types, with human-labeled expected outputs. This is a research-grade dataset that academic researchers, other hackathon teams, and competitors can use; it establishes DenialDefender as the canonical benchmark for denial-appeals AI. All three categories are Apache 2.0 licensed, with a CONTRIBUTING.md and a clear governance model (maintainers from the DenialDefender team, external contributions welcome via PR).
  3196→
  3197→## 38.2 What Should Remain Proprietary
  3198→
  3199→Three categories of artifacts remain proprietary. First, the curated payer policy corpus — the ~4,000-clause curated corpus of top 20 payers' appeal policies, denial codes, submission requirements, and historical changes. This corpus is 6-12 months of legal and clinical curation work; open-sourcing it would give competitors a 6-month head start. The corpus is exposed via API (paid tiers get full access; free tier gets sample clauses) but never as raw data dumps. Second, the appeal outcome learning data — the corpus of recorded appeal outcomes (win/loss × payer × denial type × winning argument). This is the data moat (Section 36.4); open-sourcing it would destroy the moat. The Outcome Learning Agent's weights are exposed via API (the insights panel) but never as raw outcome data. Third, the Gemma fine-tune — the fine-tuned Gemma 4B model for appeal letter tone matching. The fine-tune is trained on proprietary appeal letter exemplars; open-sourcing the weights would expose the training data indirectly. The Gemma fine-tune is served via Vertex AI Model Garden; access is via the API only.
